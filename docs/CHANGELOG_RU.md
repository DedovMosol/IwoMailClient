# История изменений

Журнал ведётся на двух языках: русская версия — этот файл, английская — [CHANGELOG_EN.md](CHANGELOG_EN.md), запись добавляется в оба файла одним коммитом.
Версия: MAJOR.MINOR.PATCH + буква пререлиза (a — alpha, b — beta, rc — release candidate).

## v1.7.0 (не выпущена)

### Почта и цепочки
- На EAS 14+ письма в цепочке упорядочены по `ConversationIndex`: сначала исходное, затем ответы. На Exchange 2007, где этого поля нет, порядок по дате, новые сверху.
- Без ConversationId (EAS 12.x) ответ присоединяется по теме, только если у него префикс ответа с двоеточием и с этой темой есть ровно одно исходное письмо. Распознаются также SV, VS, Enc, Od, YNT, Doorst, RES и REF, а однобуквенные R: и I: ответом не считаются.
- Связь по Message-ID важнее темы, учитываются все id из In-Reply-To и References. In-Reply-To берётся из MIME при загрузке тела, на Exchange 2007 через EWS GetItem (`item:InReplyTo`), и хранится в `emails.inReplyTo`.
- В цепочке Входящих видны ответы из «Отправленных» и наоборот, черновики в цепочки не попадают. Письма парной папки читаются, только когда цепочки включены, поиск группирует результаты так же.
- Свёрнутая цепочка показывает сводку последнего письма. Раскрытая показывает узкую полосу «Свернуть цепочку» и все письма, новые сверху, а в режиме выбора нажатие на полосу выделяет цепочку.
- В «Отправленных» и «Черновиках» строка и аватар показывают получателя из Кому, при пустом Кому первого из Копии, затем из Скрытой копии. Поиск показывает этих же получателей вместо отправителя.
- Множественный выбор работает протягиванием по списку, выбранные письма обрабатываются пакетно.
- При быстрых нажатиях на звезду на сервер уходит только последнее, а при отказе звезда возвращается к последнему подтверждённому сервером значению, в том числе после перезапуска. Ответ синхронизации, запрошенный до нажатия, её не перезаписывает, отказ сервера показывается тостом.
- Перенос и удаление в корзину сразу отправляют MoveItems, синхронизация папки выполняется только при Status=1 (устаревший ServerId на EAS 12.1). Строки исчезают из списка сразу и возвращаются, если сервер отказал или ничего не перенёс; после смены ServerId письма сопоставляются по содержимому снимка, поэтому перенос не задевает другое письмо.
- Окончательное удаление сначала обычной синхронизацией обрабатывает изменения папки, затем удаляет письма пакетом с текущим SyncKey. Письма, перенесённые в «Удалённые» из Outlook, больше не теряются, а неудачное удаление на Exchange 2007 не сбрасывает состояние синхронизации на сервере. Удаление из карточки письма закрывает экран один раз, после тоста.
- Если при загрузке тела сервер отвечает Status 6, письмо не удаляется и не скрывается. Экран один раз синхронизирует папку и закрывается, только если письма на сервере действительно нет (Exchange 2007 так отвечает во время полной ресинхронизации).
- Тело письма по EAS запрашивается как HTML или текст без полного MIME, а для «Отправленных» на Exchange 2007 нет предварительной загрузки MIME-заголовков, поэтому письма с крупными вложениями открываются без бесконечной загрузки. Тело не перезагружается при повороте экрана.
- Для пустого тела в «Отправленных» на Exchange 2007 EWS-запрос ищет письмо и по `item:DateTimeSent`, сравнивает тему без учёта регистра и допускает расхождение времени до 10 минут. Если после обновления сервер не вернул тело, показывается тост.
- HTML извлекается из MIME разбором частей по boundary (RFC 2046), поэтому письмо больше не обрезается на первом `--` в условных комментариях Outlook или в `-----Original Message-----`.
- В просмотре письма владелец жеста определяется один раз после системного порога касания (`TouchDirectionLock`): горизонтальная прокрутка и масштаб принадлежат WebView, вертикальная прокрутка экрану. Высота WebView учитывает `documentElement`, эффекта края нет.
- Санитайзер HTML работает за линейное время, поэтому письмо-яд не подвешивает экран. Он вырезает `<iframe>`, `<object>`, `<embed>`, `<applet>`, `<meta http-equiv="refresh">`, `data:text/html` и `javascript:` в `xlink:href`, а ссылки в теле ищутся в фоне ограниченным регулярным выражением.

### Черновики и отправка
- Сохранение черновика выполняет один `DraftSaver` для экрана и `ComposeViewModel`. Правка только текста, темы, получателей или важности идёт через EWS UpdateItem, и черновик сохраняет свой id и серверные вложения, а любое другое изменение создаёт новую версию и затем удаляет прежние по id.
- Без связи правка черновика сохраняется на устройстве (`local_draft_d_`) вместе со списком серверных версий, которые она заменяет. Синхронизация сначала загружает её на сервер и только потом удаляет старые версии, а если сервер отказал в новой версии, старая остаётся. В настройках можно включить режим, в котором черновики сохраняются только на устройстве.
- Черновики синхронизируются без `TruncationSize`, а усечённое или текстовое тело EAS не используется как тело черновика. Открытие серверного черновика обновляет тело по точному id, пустой черновик не сохраняется, пока редактор готовит HTML.
- Скрытая копия хранится локально. Неизвестную скрытую копию черновика Outlook (EAS до 16.0 её не передаёт) приложение читает через EWS из прежней версии, а если это не удалось, прежняя версия не удаляется; опустошённые Кому, Копия и Скрытая копия очищаются через `DeleteItemField`, важность сохраняется.
- Вложения, которые редактор не успел загрузить, скачиваются при сохранении. Если скачать не удалось при доступном сервере, сохранение завершается ошибкой вместо потери вложения, а без связи вложение переносится по ссылке.
- Вложение считается встроенным, если у него `isInline` или есть Content-ID, и это правило одинаково при синхронизации и сверке, поэтому картинка не дублируется в теле и в списке файлов. Картинки повторно открытого черновика сопоставляются со своими `cid:`, и правка текста снова идёт через UpdateItem.
- Поиск черновика по теме срабатывает только при единственном совпадении, поэтому обновление и удаление не задевают другой черновик с той же или пустой темой. Черновик с EWS-id удаляется через EWS на любой версии Exchange, черновик, у которого удалили все вложения, пересоздаётся, а после отправки серверный черновик удаляется и с сервера.
- Черновики устройства загружаются на сервер с вложениями, Скрытой копией и важностью, двойное нажатие «Сохранить» запускает одно сохранение. Отложенная отправка хранит тело в файле, потому что `Data` WorkManager ограничена 10 КБ.
- Отправка и сохранение черновика выполняются в `RetainScopeViewModel`: поворот их не прерывает, они не идут одновременно, «Назад» во время них не закрывает экран, а после ошибки кнопка «Отправка» не залипает.
- Суммарный размер файлов и встроенных картинок (лимит 10 МБ) проверяется до чтения байтов в память, при отправке и при сохранении черновика. Адреса проверяются перед отправкой, отправка разрешена, если заполнено любое из полей Кому, Копия или Скрытая копия.
- Длинная тема кодируется по RFC 2047 несколькими encoded-word. Адреса и Message-ID во всех путях сборки письма, включая отчёты о прочтении, очищаются от CR/LF, а постоянный `ClientId` исключает повторную отправку из очереди.
- Текст редактора длиннее 10 000 символов сохраняется в файл (`LargeStateSaver`), поэтому сворачивание черновика с картинками не вызывает `TransactionTooLargeException`, а тело переживает смерть процесса. Набранный текст, удалённая подпись и загруженный ответ или пересылка не сбрасываются при повороте.
- При падении рендерера WebView редактор пересоздаётся один раз, при повторном падении показывается сообщение, а текст остаётся доступным для отправки и сохранения. Большой HTML обрабатывается вне главного потока, нехватка памяти на огромном теле не роняет приложение, а Content-Security-Policy и санитайзер вырезают `on*` и `javascript:`, в том числе при вставке.
- Цитата при ответе и пересылке подписана на языке интерфейса («От», «Дата», «Тема», «Кому»). Подпись с `$` и `\` подставляется без искажений, mailto сохраняет подпись под переданным текстом. Подсказки получателей ищут по группам, контактам, истории адресов и GAL с задержкой после ввода.

### Вложения
- Вложения скачиваются потоком в файл, без чтения в память: ItemOperations Fetch с `MS-ASAcceptMultiPart: T`, на EAS 12.x GetAttachment запросом POST, затем EWS GetAttachment с потоковым декодированием base64. Открытие, сохранение, «Поделиться» и перетаскивание работают с файлом; через EWS проверено 30 МБ, по EAS Exchange 2007 отдаёт вложения до своего лимита (выше отвечает Status 11).
- Потоковый ответ EAS читается и закрывается в том же контексте корутины, поэтому выход с экрана во время загрузки не оставляет открытое соединение. Отмена останавливает загрузку и удаляет временные файлы `.part`.
- Ответ, оборванный внутри EWS `Content`, считается ошибкой, а не более коротким файлом. Пустое вложение, которое подтвердил EWS, сохраняется пустым файлом вместо ошибки «не найдено».
- «Сохранить» и «Сохранить как…» доступны для всех вложений, выбор файла переживает поворот экрана. На Android 10+ «Сохранить» пишет в «Загрузки» через MediaStore, на Android 8–9 открывает системный диалог, а если запись не удалась, пустой документ в выбранной папке удаляется.
- Убран запасной путь, который при ошибке сохранял всё письмо вместо вложения. Base64 во вложениях MIME разбивается строками с CRLF (RFC 2045).
- «Поделиться» копирует файлы в фоне, не больше 10 МБ, и сообщает тостом о пропущенных. Временные файлы вложений ответа, пересылки и черновика удаляются по возрасту, файлы, на которые ссылаются черновики, сохраняются и хранятся в `filesDir`.

### Календарь
- Встреча с участниками на Exchange 2010/2013 создаётся и меняется через EWS с `SendToAllAndSaveCopy`, поэтому участники получают приглашения и обновления (по EAS 14.x сервер их не рассылает). Элемент ищется по прежней теме и времени, серия адресуется главным элементом.
- При правке встречи поле участников заполнено, имена и ответы участников отправляются обратно. Правка участника никому не рассылается и сохраняет `MeetingStatus`, который читается по битовым флагам, а тост «Приглашение отправлено» появляется, только если организатор добавил участников.
- Исключения серий на Exchange 2007 дополняются через EWS: FindItem запрашивается без `item:Body` и `calendar:OriginalStart`, они берутся через GetItem, а неполный ответ ничего не меняет. Дополнение не перезаписывает правку вхождения, сделанную во время синхронизации, а правка одного вхождения сливается со свежей строкой БД внутри транзакции (PIM-28).
- В событиях есть вложения, повторяющиеся события и локальная корзина. Вложения повторяющихся событий хранятся метаданными без копий байтов, на Exchange 2007 загружаются по главному ItemId серии, кэш предпросмотра чистится по возрасту.
- Ежедневные и недельные серии с COUNT считаются верно, в том числе в локалях с понедельником в начале недели. Переход через месяц и год работает, поле времени не падает на «9999» и держит курсор в конце.
- Событие удаляется локально только после подтверждения сервера, а удаление встречи участником сначала отправляет отказ (`MeetingResponse` или EWS `DeclineItem`). Удаление и восстановление идут под той же блокировкой, что и синхронизация, поэтому удалённые события не возвращаются.
- Время со смещением вместо UTC разбирается через `Instant.parse` без сдвига. Дата и время в диалоге создания события не сбрасываются при повороте.

### Задачи, заметки, контакты
- Задачи и заметки создаются, правятся и переносятся в корзину без связи: изменение сохраняется на устройстве, встаёт в очередь `pending_pim_changes`, а тост сообщает, что оно отправится при появлении связи. Отправка идёт тем же путём, что и онлайн (EAS на Exchange 2010+, EWS на 2007), назначение задачи без связи даёт ошибку.
- Несколько правок одной записи уходят одним итогом, правка во время отправки не теряется, синхронизация не перетирает ждущую правку. Восстановление из корзины до отправки выполняется только на устройстве, а окончательное удаление, очистка корзины и сброс сначала отправляют очередь.
- Неполный ответ сервера (HTTP-ошибка, обрыв, усечённый WBXML или SOAP, лимит страниц) не удаляет локальные задачи, заметки и контакты. Страницы контактов разбираются целиком, сбой до первого контакта возвращается ошибкой.
- Восстановление и окончательное удаление задачи из корзины на Exchange 2010/2013 находят её копию через EWS, а отказ `DeleteItem` возвращается ошибкой. «Выполнено» из напоминания о задаче при ошибке сервера повторяется до 10 раз, категории заметок EWS читаются.
- В меню Календаря, Задач и Заметок есть «Сбросить и пересинхронизировать»: локальная копия аккаунта стирается и загружается с сервера заново, сервер не затрагивается.
- При написании письма можно выбрать группу контактов, при добавлении уже указанного адреса появляется предупреждение.

### Синхронизация и работа без связи
- Звезда, «прочитано» и перенос без связи сразу применяются на устройстве, встают в очередь `pending_email_changes` и отправляются `PendingMailChangesWorker`, когда появляется сеть, в том числе после перезапуска. Откат выполняется только при явном отказе сервера, а устаревший SyncKey, ошибки сервера и таймауты повторяются позже.
- Полная ресинхронизация (SyncKey=0) не удаляет письмо с ожидающим переносом и не создаёт его дубль во Входящих. Перенос отправляется из исходной папки, а если письмо уже в целевой, очередь очищается.
- `FolderSyncGate` пропускает только один запрос Sync на папку одновременно, SyncKey перечитывается из БД внутри шлюза. Отдельной полной синхронизации «Отправленных» нет: устаревший ключ исправляет обычная синхронизация, а без связи ключ не сбрасывается.
- При открытии Входящих, Отправленных и пользовательских папок выполняется тихая инкрементальная синхронизация, не чаще раза в 30 секунд на папку и без индикатора обновления. Корзина автоматически не синхронизируется, «Черновики» синхронизируются один раз.
- Push без push-аккаунтов не перезапускается по кругу, воркер перезапуска не повторяет попытки бесконечно. На Android 15 запуск после загрузки идёт через WorkManager, watchdog регистрируется динамически и работает на Android 8+.
- При возврате приложения на передний план push запускает догоняющую синхронизацию. Блокировка на аккаунт (`Mutex.tryLock`) исключает две одновременные синхронизации одного аккаунта и полную ресинхронизацию из-за их гонки.
- Таймаут синхронизации переключает на резервный сервер, только если текущий не отвечает по TCP, и не вызывает полной ресинхронизации. Сеть только с интранетом считается подключённой, проверка доступности укладывает DNS в свой таймаут и использует системный HTTP-прокси, а `host:port` в адресе сервера важнее порта аккаунта (IPv6 в квадратных скобках).
- Автоочистка папок выключена по умолчанию и удаляет только письма, которые лежали в папке уже при проверке N дней назад, а перевод часов назад начинает отсчёт заново. Черновик удаляется, только если не менялся N дней, вместе с файлами.
- Напоминания ставятся точным будильником, а без разрешения будильником в режиме ожидания или обычным. Воркер напоминаний повторяет попытку и останавливается после 5 неудач.

### Совместимость с Exchange 2007–2013 (EAS и EWS)
- На Exchange 2007 SP1 загружаются все задачи и события календаря, синхронизация папок исправлена. `DeviceId` EAS и даты EWS форматируются с `Locale.US`. На языках с нелатинскими цифрами (персидский, арабский, бенгальский и другие) запросы больше не ломаются, а сервер не видит новое устройство при смене языка телефона.
- NTLM для EWS дочитывает ответ 401 и проходит рукопожатие на отдельном клиенте с `ConnectionPool(1)`, поэтому параллельные запросы не перехватывают аутентифицируемое соединение и случайных 401 нет. SOAP Fault от EWS возвращается ошибкой, а не пустым телом.
- `DeviceInformation` в Provision отправляется только на EAS 14.1, на 12.x и 14.0 сведения об устройстве уходят командой Settings. Повтор после HTTP 449 отправляет правильно собранное тело запроса.
- Снятый флаг отправляется пустым `<Flag/>` ([MS-ASEMAIL]), флаг без дат после Status 6 повторяется с сегодняшними датами, новый SyncKey сохраняется и при отклонённом Change. Кодировщик WBXML больше не переносит пространство имён пустого элемента на следующие элементы.
- При Ping Status 5 принимается `HeartbeatInterval`, предложенный сервером, в пределах 120–1800 секунд. Exchange-аккаунты работают только по HTTPS, нерабочая опция HTTP убрана.

### Доверие серверу и TLS
- Если система не подтверждает сертификат, при добавлении аккаунта показывается диалог: кому и кем выдан, срок, имена, SHA-256 и SHA-1, а также вердикт системной проверки. Сертификат берётся рукопожатием без учётных данных и показывается, даже если сервер требует клиентский сертификат.
- «Доверять» закрепляет открытый ключ сервера, после чего принимается только этот ключ, без проверки имени и срока. Если система уже доверяет сертификату (УЦ и имя хоста), диалог предлагает «использовать системную проверку» вместо закрепления.
- В настройках аккаунта без файла сертификата есть «Доверять сертификату с сервера», но для аккаунтов, которые проходят системную проверку, этот пункт не предлагается. У резервного сервера свой закреплённый ключ, изменившийся сертификат записывается в слот того сервера, где замечено изменение.
- Ошибка настройки SSL в режиме закрепления или импортированного сертификата прерывает соединение, а не переходит на системное доверие без проверки имени хоста.
- Импортированный сертификат принимается при совпадении ключа листа и сроке действия, иначе цепочка проверяется PKIX с ним как якорем, затем системным хранилищем. Цепочка, которая лишь содержит импортированный сертификат, больше не принимается.
- Имя хоста проверяет `Rfc6125HostnameVerifier` на публичных API: сначала SAN, CN только если ни одна запись SAN не подошла, подстановка только в левой метке. Самоподписанный сертификат Exchange 2007 без SAN продолжает работать.
- IMAP и POP3 без SSL требуют STARTTLS/STLS и проверяют имя хоста, закрепление работает и там, а `socketFactory.fallback=false` не даёт JavaMail его обойти. TLS 1.0 и 3DES разрешены последними в списке для Exchange 2007 на портах 993/995, ошибки разбираются по всей цепочке причин.

### Блокировка приложения и приватность
- Приложение можно закрыть паролем и отпечатком. Пароль хранится как PBKDF2-HMAC-SHA256 с 600 000 итераций и случайной солью в `EncryptedSharedPreferences`, приложение блокируется при уходе в фон и при холодном старте, а вводимые пароли не попадают в сохранённое состояние экрана.
- После 5 неверных паролей вводятся паузы 30 с, 1 мин, 5 мин и 15 мин по `elapsedRealtime`, поэтому перевод часов их не сокращает. Попытка засчитывается до проверки, на экране блокировки виден обратный отсчёт и число попыток, успешный вход сбрасывает счётчик.
- При включённой блокировке на Android 13+ «Недавние» не хранят снимок окна (`setRecentsScreenshotEnabled`), а скриншоты внутри разблокированного приложения остаются. На Android 8–12 в это время действует FLAG_SECURE.
- Уведомления о письмах, напоминаниях, отправке и проблемах связи используют VISIBILITY_PRIVATE с версией без содержимого. При включённой блокировке приложения содержимого нет и в шторке, а уже показанные уведомления перевыставляются без содержимого в момент включения.
- Виджет при включённой блокировке показывает только счётчики, без отправителей, тем, событий и задач, и обновляется сразу при её переключении.
- Если Keystore недоступен, пароли хранятся в обфускации с PBKDF2 (10 000 итераций), а приложение сообщает об этом тостом. В разделе «Безопасность» есть переключатель fail-closed: в этом режиме пароли не пишутся в обфускацию, а новый ящик без сохранённого пароля не создаётся.
- `data_extraction_rules.xml` исключает всё приватное хранилище из переноса между устройствами на Android 12+, включая клиентские сертификаты, вложения и очередь исходящих.

### Уведомления и виджет
- Пока приложение открыто, уведомления о новой почте не показываются, письмо сразу появляется в списке. Эти письма не всплывают уведомлением и после ухода в фон.
- Нажатие на напоминание о событии, задаче или флаге переключает на нужный ящик и открывает эту запись, даже если на экране был другой аккаунт.
- Запросы разрешений показываются по одному после онбординга (уведомления, фоновая работа, точные будильники) в общем стиле диалогов, у каждого своя иконка.
- Виджет обновляется после каждой синхронизации push. Последние письма берутся только из непрочитанных во Входящих лёгкими запросами без тел, обновления виджета не идут параллельно.
- Нижний ряд узкого виджета не обрезается: число и размер аватаров подстраиваются под ширину. Для сегодняшних писем и синхронизации показывается время, для более старых дата.
- Текст виджета на цвете темы сплошной белый. Раньше он был белым с прозрачностью 50–80% и давал контраст 1,8–2,8:1.

### Интерфейс и настройки
- Настройки в стиле HyperOS: крупный заголовок на градиенте темы сворачивается при прокрутке, белые карточки без разделителей на светло-серой странице (в тёмной теме тёмно-серые на чёрной), значение справа со стрелкой. Около десяти диалогов с радиокнопками заменены общим `SettingsChoiceRow`, автоочистка задаётся строкой на каждую папку, поиск по настройкам находит цвет скроллбара, анимации, смену пароля и настройки аккаунта.
- Короткий выбор (до 5 вариантов) открывается выпадающим списком у строки, длинный нижним листом. Длинный выбор внутри нижнего листа открывается выпадающим списком, а не вторым листом.
- Без dynamic color контейнеры и поверхности берутся из выбранной темы, а не из фиолетовой схемы M3. Карточка «Защита от подмены сервера» использует цвета темы и локализованные строки, без эмодзи.
- Режим темы (светлая, тёмная или как в системе) выбирается в «Персонализации» и на онбординге, иконки системных панелей следуют теме приложения.
- Жёлтая тема стала темнее (`#A86400`/`#8F4F00`), чтобы белый текст на панелях и кнопках давал контраст не ниже 4,5:1. Этот порог для текста проверяется во всех темах.
- Выделение в списках и звезда дают короткий тик `VibrationEffect`, долгое нажатие более сильный импульс, тик есть и при автоскролле выделения. На API 33+ импульс помечен `USAGE_TOUCH`, а при выключенном системном виброотклике вибрации нет.
- В контактах такая же отдача при выделении, как в почте: тик при переключении и более сильный импульс при долгом нажатии. Долгое нажатие с протягиванием даёт одну вибрацию, а не две, начало перетаскивания вложения тоже вибрирует.
- Системный «Назад» в режиме выбора снимает выделение в почте, поиске, задачах, заметках и контактах. В настройках почты две строки «Свайп вправо» и «Свайп влево» с текущим действием, на панели фильтров есть кнопка «Сбросить все».
- Слайды онбординга появляются с анимацией, когда становятся текущими или целью свайпа, соседний слайд при свайпе не пустой. Обновлены элементы интерфейса, добавлены собственные иконки типов файлов и дополнительные скроллбары.
- У звезды и значка вложения есть подписи для TalkBack, мелкие кнопки увеличены до 48 dp. Около 50 сообщений об ошибках репозиториев и EAS, ошибки экрана написания письма и диалог очистки корзины календаря переведены на язык интерфейса.

### Стабильность и производительность
- Почта, письмо, поиск, задачи, заметки, папки, экран написания и настройки синхронизации работают через ViewModel: состояние и начатые операции переживают поворот экрана. Диалог доступного обновления тоже переживает поворот.
- Операции экранов, фоновая работа, push, будильники и приёмники выполняются в защищённых scope: ошибка БД или ввода-вывода логируется и не роняет процесс.
- При падении рендерера WebView в просмотре письма и печати WebView пересоздаётся, после повторного падения показывается текст письма. WebView просмотра освобождается при пересоздании.
- При нехватке памяти тяжёлое письмо открывается без встроенных картинок, а inline-картинки не строятся из чрезмерно больших писем.
- Обработка тела письма, распознавание приглашений и разбор iCal кешируются и не повторяются на каждой рекомпозиции, а невидимая анимация в списке писем не перерисовывается каждый кадр. Экраны собирают потоки с учётом жизненного цикла.
- Звезда, окончательное удаление, перенос, виджет и сверка после полной ресинхронизации читают лёгкие проекции без тел писем, для запросов виджета добавлены индексы.
- Ответы OkHttp закрываются и при ошибке, и при отмене корутины (проверка обновлений, транспорт EAS, Ping), соединения не утекают. Кэш EAS-клиентов потокобезопасен, гонка при переключении на резервный сервер устранена.
- Очистка дублей писем группирует по Message-ID и не удаляет разные письма с одинаковыми темой, отправителем и временем.
- Push-сервис на Android 12+ не падает с `ForegroundServiceStartNotAllowedException`. Отказ прошивки открыть настройки приложения при откате обновления не роняет процесс.
- Настройки темы не перезаписываются эхом собственной записи DataStore, сохранённый режим темы виден сразу после перезапуска без `runBlocking` на главном потоке. DataStore 1.1.1 исправляет ошибку записи «Unable to rename», а каждая запись в цепочке `putString` обфусцированного хранилища обфусцируется. `LargeStateSaver` читает и удаляет только свои файлы в `cacheDir`, файлы старше 24 часов удаляются при запуске.
