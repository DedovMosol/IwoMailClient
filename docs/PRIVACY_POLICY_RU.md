# Политика конфиденциальности

Для исходной версии 1.7.0 · обновлено 20 ноября 2026 г. · [English](PRIVACY_POLICY_EN.md)

## Кто получает данные

В iwo Mail Client нет сервиса разработчика, через который проходит почта, рекламных SDK или автоматической отправки аналитики. Это не означает, что данные никогда не покидают устройство:

- **Почтовый сервер** получает данные для входа и синхронизации. Для Exchange клиент использует EAS и EWS: в зависимости от операции передаются письма, вложения, черновики, контакты, события, задачи и заметки. Direct Push соединяется непосредственно с Exchange. Режимы IMAP и POP3 получают почту; SMTP-отправки нет. Обмен с сервером защищён TLS; возврата на обычный HTTP для старых Exchange нет.
- **Серверы внешних изображений и шрифтов** могут получить IP-адрес, время запроса и идентификатор в URL. Во входящем HTML-письме их загрузка по умолчанию запрещена. Её можно разрешить для одного письма, доверенного отправителя или всех писем. Для «Отправленных», «Черновиков» и HTML-описаний событий календаря просмотр разрешает внешние ресурсы. Встроенная картинка из самого письма не требует запроса к сайту отправителя.
- **При переходе по ссылке** веб-адрес передаётся внешнему приложению. При выбранной пользователем однокликовой отписке клиент отправляет запрос на HTTPS-адрес из письма без пароля ящика; сам адрес может идентифицировать подписку. Ссылка `mailto:` открывает редактор письма.
- **При проверке обновлений** клиент запрашивает [описание версии](../update.json) на GitHub. Пароль ящика и содержимое почты в этот запрос не входят. Для скачивания используется URL выбранного APK из описания версии. Хост загрузки видит обычные данные соединения, в том числе IP-адрес. Уведомление о найденной версии показывает само приложение; установка и удаление при откате требуют подтверждения Android.

## Что остаётся на устройстве

В закрытом хранилище приложения находятся база Room с локальной почтой и другими данными ящиков, настройки, подписи, кэш вложений, очереди отправки, данные синхронизации и локальные диагностические записи. Локальная копия письма не заменяет серверную. Почтовая база и файлы вложений не шифруются приложением отдельно.

Пароли ящиков и клиентских сертификатов обычно хранятся в `EncryptedSharedPreferences` с ключом Android Keystore. Если защищённое хранилище недоступно, запасной режим использует **обфускацию, а не шифрование**. Запись новых паролей в этом режиме можно запретить. Импортированный файл сертификата копируется в закрытое хранилище как есть. Блокировка приложения хранит проверочный хеш пароля; биометрию проверяет Android. Условия [восстановления блокировки](SECURITY_RU.md) отличаются от обычного входа.

Системное резервное копирование приложения отключено; правила Android 12+ также исключают приватные данные из переноса на другое устройство. Это не распространяется на сохранённые в «Загрузки» файлы, выгруженные контакты или копии, переданные другому приложению.

## Разрешения и действия пользователя

Доступ к сети нужен для почты, внешних ресурсов и обновлений. Фоновая служба, автозапуск после перезагрузки, точные будильники и исключение из оптимизации батареи используются для синхронизации, отложенной отправки и напоминаний. Приложение использует уведомления и вибрацию; разрешения биометрии нужны для необязательного входа по отпечатку. Разрешения установки и удаления пакетов относятся к обновлению и откату APK.

При «Поделиться» текст и выбранные файлы могут попасть в черновик и затем на сервер при сохранении или отправке. Открывая вложение во внешнем приложении, пользователь предоставляет ему доступ к файлу; печать передаёт документ системе печати Android. На виджете и в уведомлениях могут быть видны данные почты. При включённой блокировке содержимое писем скрывается. На большом виджете остаются названия ящиков и их счётчики непрочитанных. Нажатие на такую строку требует разблокировки приложения; тему и отправителя лаунчер из этой строки не получает.
